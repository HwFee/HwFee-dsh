# @hwfee/dsh-usage-stats

DeepSeek Harness (DSH) 的本地会话用量看板插件。

装上之后，每次打开新对话空白页，问候语下方会多出一张统计卡片：看看你一共开了多少次会话、发了多少条消息、烧了多少 Token、最常在几点干活、最爱用哪个模型，外加一张活跃度热力图和一句按经典小说字数折算的对比。

所有数据都从你本机 `~/.dsh/sessions` 下的会话日志里聚合，纯本地计算，不发任何外部请求。

## 安装与卸载

在命令行运行，或在 DSH 的 **设置 → 插件 → 添加插件** 里直接输入 `@hwfee/dsh-usage-stats`：

```bash
dsh plugin --profile desktop add @hwfee/dsh-usage-stats
```

**装完或卸完后必须彻底退出并重开 DSH。**

卸载：

```bash
dsh plugin --profile desktop remove @hwfee/dsh-usage-stats
```

## 看板里有什么

1. **两个标签页 + 三个时间范围**
   - 左上角切换 **「总览」** 和 **「模型」**（按 Token 消耗从高到低列出每个模型的用量和占比条）。
   - 右上角切换 **「全部 / 30 天 / 7 天」**，实时重算六张卡片和模型列表的数字。
2. **六张核心指标卡**
   - 会话数（只算真正发过 `user/message` 的会话，空会话不算；**已删除的会话仍然算**，见下文第 3 条）、消息总数、总 Token、活跃天数、高峰时段（12 小时制）、最常用模型。
3. **活跃度热力图**
   - 7 行 × N 列，**右下角那一格永远锚定「今天」**，从今天往前回溯填满整周，不会出现缺半截的尾列或未来日期。鼠标悬停在格子上会显示当天的日期与消息数。
4. **小说字数折算**
   - 底部每次打开新会话随机抽一本书（《红楼梦》73 万字、《三国演义》63 万字、《围城》23 万字、《活着》12 万字、《骆驼祥子》10 万字），算算你用掉的 Token 大概能印几本。挂载后固定，切换时间范围不会乱跳。

## 设置项（样式、高度与数字单位）

如果同时装了 `dsh-cds-theme`，下面这三行设置会自动出现在 **设置 → 主题定制** 最底部；没装主题插件时，它们会自动落回 **设置 → 通用设置**：

- **面板样式**：两个平铺按钮——
  - **现有**（`classic`，**默认**）：宽度跟随输入框，六宫格铺满，热力图有自己的底衬，说明行上方有一条分隔线。这是升级前的老样子，默认值就是它，所以升级不会改变任何人的界面。
  - **参考**（`compact`）：参考 Claude 风格用法面板（[Nwflower/dsh-claude-style](https://github.com/Nwflower/dsh-claude-style)）的 **480px 居中卡片**：整卡一层浅wash，格子比卡面深一档，热力图直接画在卡上、没有底衬，说明行上方没有分隔线。强调色用的是**项目自己的 accent**（`--dsw-alias-state-business-primary`），不是参考实现里那个固定蓝。

  切换是**一个属性翻转**，不重挂载、不刷新；选择写进 `localStorage`。

- **用量面板高度**：滑块 `240–520 px`（步进 4px）。**两种样式各自记住自己的高度**——
  - 现有样式默认 **344px**，参考样式默认 **252px**（480px 卡片在默认字号下正文刚好放得下热力图与说明行的自然高度，正好落在滑块的 4px 网格上）。
  - 滑块永远在调**当前显示的**那种样式：切到参考样式，读数就是 252；切回现有样式，读数回到 344，参考样式你调过的值不会被改写。

  调小高度时，总览页会按「先缩热力图格子 → 再收间距 → 最后微调卡文字号」的顺序等比缩放，**绝不会出现竖向滚动条**；两个标签页共用同一个高度，切换标签时底下的输入框不会上下乱跳。

- **数字单位**：开关切换 **万/亿**（`1.2万`、`1.23亿`）或 **K/M/B**（`1.2K`、`123M`），默认跟随界面语言（中文用万/亿，英文用 K/M/B）。

### 输入框里写很长时，面板不会被顶出去

这是 **0.1.4** 修的一个真问题。0.1.4 **尚未发布**——npm 上最新的 `0.1.3` 里没有这项修复（它的 `client/client.js` 既没有 `--dus-input-budget`，也没有「参考」样式），要这项修复请等 `0.1.4` 发布后安装 `@hwfee/dsh-usage-stats@0.1.4`：在新对话页往输入框里粘几十行，宿主会把编辑器撑到它自己的 336px 上限，加上上面的面板就把整列顶出可视区；宿主又是**居中**布局，溢出量上下各分一半，于是面板被摆到滚动原点**之上**——滚到最顶也看不见它。

现在的做法（只在本插件面板可见时生效，离开空白页立即还原）：

- 面板在挂载时量一次**滚动容器的可用高度**与**不随输入增长的固定部分**（问候语、面板本身、模式行、输入卡的内边距与工具条），据此写一个自有变量 `--dus-input-budget` 到输入卡上。
- 输入区的 `max-height` 变成 `min(宿主的 --dsh-composer-text-max-height, --dus-input-budget)`：**谁更紧谁生效**。装了 cds-theme 就用它的更紧的值，没装就用这里的预算；两边都不改对方的变量，也不做自引用。
- 预算只跟**固定部分**有关：文字长高多少，输入区就长高多少，两者相减后不变，所以不会出现「缩小自己 → 预算变大 → 自己又变长」的来回抖动。加附件、工具条换行这类真正变高的东西会让预算变小。
- 输入区最小只压到**一行真实高度**（行高 + 内边距，宿主约 36px，带外内边距的分栏输入约 56px）。再装不下就由**页面**滚动，并且顶对齐（`safe center`），保证面板顶端始终可达——不会为了塞下所有东西把编辑器压成看不到光标。

## 几个容易踩坑的实现细节

### 1. 为什么要自己按魔数切 zstd 帧

DSH 的会话日志（`*.zstd`）是**多个 zstd 压缩帧首尾直接拼接**写进去的。如果直接拿 Node 自带的 `zlib.zstdDecompressSync` 去解整个文件，它只会解出第一帧，后面追加的所有对话都会被静默丢掉，算出来的 Token 少一大截。

`lib/usage-store.js` 的做法是按 zstd 帧魔数（`28 B5 2F FD`）把文件切开，逐帧解压后再按行解析 JSON。

### 2. 为什么第一次打开要 2 秒，之后只要 20 毫秒

百来个会话文件大约有 50 MB 压缩数据、两万多个 zstd 帧。第一次冷启动全量解压需要约 2 秒；解析完后，每个文件的摘要会按 `(路径, mtimeMs, size)` 持久化写进 `~/.dsh/cache/usage-stats/`（故意不放系统临时目录，防止被 Windows 存储感知定期清掉）。之后每次重启 DSH 并在后台分批预热，打开新会话几乎是瞬开。

### 3. 为什么删了会话，统计不会变少

看板的数字不是「磁盘上现在有什么」，而是一本**累计账本**：每个会话一行，存在 `~/.dsh/cache/usage-stats/ledger-<哈希>.json`。会话继续写的时候整行替换，日志被删掉时**行不删**。

- **归档**：只往宿主的 `workspace.json` 里加一个 id，日志原地不动——有没有账本都会被统计。
- **删除**：真的删掉 `~/.dsh/sessions/.../<会话>/session.v4.jsonl.zstd`，只有账本还记得它。
- 数字因此**只增不减**。想清零就删掉 `ledger-<哈希>.json`（下一次打开会从现存日志重建）；`?refresh=1` 只重读日志，不动账本。
- 账本只存计数（消息数、Token、按天/小时/模型），不存提示词、不存路径。

### 4. 为什么完全跟随宿主令牌

面板样式全部使用 `--dsw-alias-*` 和 `--dsw-radius-*` 宿主变量，不写死任何色值。不管你用 DSH 原生明暗主题，还是装了 `dsh-cds-theme` 切陶土橙、调圆角，看板都会自动跟着变。
