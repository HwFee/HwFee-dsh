## The two remaining differences are line endings, not content

`@hwfee/dsh-predict` reports `lib/index.js` and `dsh-system-fonts` reports
`lib/font-metadata.js` as changed. In both cases the difference is **CRLF versus LF**,
verified by comparing the published file with the working-tree file:

| Package | File | CRLF count in published | CRLF count local | Equal after normalising newlines |
|---|---|---|---|---|
| `@hwfee/dsh-predict` | `lib/index.js` | 702 | 0 | **yes** |
| `dsh-system-fonts` | `lib/font-metadata.js` | 149 | 0 | **yes** |

Why the published copy has CRLF: those files were committed with CRLF line endings at
some point, and git stores them that way in the tarball npm serves, while the working
tree on this machine holds the LF form (`git` reports the tree clean because the
checkout is consistent with the index). The bytes differ; the code does not.

This is recorded rather than "fixed" because rewriting line endings would change the
published tarball for every user to no functional end, and would invalidate the
hashes already recorded in [publish-record.md](publish-record.md) and attached to the
GitHub Releases.

**Consequence for anyone reading this file later:** a `Changed` row here does not by
itself mean the released code differs from the tree. Normalise newlines before
concluding that a file is out of sync.
